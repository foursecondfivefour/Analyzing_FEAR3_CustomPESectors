**Важно:** совпадение с манифестом подтверждает целостность относительно него, но не подлинность файлов. Первый архив не содержит EXE. Файл `forensic_summary.json` — входное утверждение, а не результат новой проверки.

Все 31 предоставленные секции совпали с EXE побайтово по указанным сырым смещениям. Также совпали индекс, исходные 8 байтов имени, RVA, виртуальный размер, смещение, размер, характеристики и SHA-256 каждой секции. Это подтверждает соответствие секций этому EXE, но не подлинность самого EXE.

Статический инвентарь `evidence/pe-inventory.json` создаётся командой:

```sh
python tooling/pe_inventory.py 'evidence/source-exe/F.E.A.R. 3.exe' --output evidence/pe-inventory.json
```

EXE — PE32 x86, база образа `0x400000`, RVA точки входа `0xB3B725`, всего 35 секций и 22 библиотеки в таблице обычных импортов. Каталог сертификатов в заголовке отсутствует; криптографическая проверка подписи не проводилась. PE-заголовок хранит контрольную сумму 0, вычисленная `pefile` — `0x1568A2D` (не SHA-256). Отчёт содержит сырые метаданные, импорты, хеши и энтропию секций; это инвентаризация, а не полный анализ кода или динамического поведения.

## Проверка

```sh
python tooling/verify.py
# Если имеется оригинальный файл: дополнительно сравнить сырые байты по raw_offset/raw_size
python tooling/verify.py --exe '/path/to/F.E.A.R. 3.exe'
```

Вторая команда проверяет размер и байты предоставленных секций, но не устанавливает подлинность всего EXE: эталонного хеша EXE в архиве нет. Хеш переданного EXE выводится отдельно. `SHA256SUMS.txt` — локально сформированная контрольная сумма; для последующих проверок сохраняйте её независимо от исследуемых файлов.

## Локальный Python-набор

Инструменты загружены через Python/pip в `tooling/python/` для Linux x86-64 и Python 3.11; папка не включается в Git. В других окружениях переустановите их (потребуются Python с pip, интернет и совместимые binary wheels):

```sh
python tooling/install.py
PYTHONPATH=tooling/python python -c 'import pefile, lief, capstone, unicorn, keystone, yara, construct, filetype, Crypto; print("OK")'
```

На Windows вместо `PYTHONPATH=...` задайте переменную окружения `PYTHONPATH` равной `tooling/python`. `tooling/requirements.txt` фиксирует версии, но не фиксирует криптографические хеши пакетов; установка требует доверия к PyPI и пути доставки. Нативные библиотеки этих пакетов зависят от платформы.

- **pefile, LIEF** — PE-структуры, секции и метаданные при наличии оригинального EXE.
- **Capstone, Keystone, Unicorn** — дизассемблирование, ассемблирование и контролируемая эмуляция x86; эмулятор не является полноценной Windows-средой.
- **YARA** — сигнатурный поиск; собственные правила необходимо подготовить отдельно.
- **Construct, PyCryptodome, filetype** — разбор бинарных структур, криптографические примитивы и распознавание распространённых сигнатур.
- Стандартная библиотека Python — хеши, байтовое сравнение и произвольный побайтовый анализ.

Этот комплект — стартовая среда, а не гарантия исчерпывающей форензики. Для полноценного анализа кода и межсекционных ссылок нужны оригинальный EXE и, при наличии, подходящая база IDA/символы; интерактивные дизассемблеры и изолированная Windows-среда в комплект не входят. Эти `.bin` — сырые секции, а не отдельные DLL; не запускайте их. Данные и инструкции могут быть перемешаны, поэтому линейная дизассемблировка всей секции даёт ложные результаты. Смещения файла, RVA и виртуальные адреса нельзя смешивать; размер на диске и виртуальный размер могут различаться.
