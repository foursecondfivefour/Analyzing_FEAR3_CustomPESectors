# Аудит совпадений PE и Lua API: скрипты и ручная проверка

## Результат

**Утверждение «все записи API совпадают с этой сборкой игры» доказать нельзя.** Проведена проверка всех 35 файловых PE-секций и всех 3879 записей каталога API. Для одной большой группы получено сильное статическое свидетельство: все **161** имени из `GameScript.Game` найдены в одном нативном регистрационном участке вместе с reflection-прокси, в RTTI которых упоминается `GameScriptGame`. При этом числовой суффикс аргументов прокси и число аргументов Lua-заглушки совпадают у 155, но **различаются у шести**.

Это различие непосредственно видно в сохранённых артефактах. Оно не доказывает само по себе несовместимость runtime-вызовов: не полностью проверены трансляция аргументов, перегрузки, дополнительные пути регистрации и происхождение API относительно конкретного EXE. Но и заявить полное совпадение по имеющимся данным нельзя.

## Что проверено автоматически

1. [Предыдущий генератор сопоставления](../../tooling/compare_script_api.py) проверяет SHA-256 EXE и закреплённого ZIP-снимка API, хеши и состав всех 622 файлов снимка, а также строки RTTI 149 найденных классов. Подробности исходного сравнения — [здесь](../script-api-comparison/REPORT.md).
2. [Новый аудит](../../tooling/audit_script_api.py) сверяет все **330** reference-документов с JSON по множествам имён каждого namespace; проверены все **3879** заголовков. Совпадение индекса и JSON не доказывает истинность документации, поскольку они происходят из общего набора артефактов.
3. Снова проверены файловые байты **35 PE-секций**, по каждой записаны размер, смещение, SHA-256 и количество полных NUL-терминированных строк, совпадающих с коротким именем записи API: [all-section-coverage.csv](all-section-coverage.csv). Исходные 31 пользовательские секции также отдельно сверены с EXE через `verify.py`. Сырые PE-заголовки, overlay, виртуальные хвосты без файловых байт и внешние DLL не входят в посекционный анализ.
4. Каждая из 3879 записей получила один из уровней в [all-api-evidence.csv](all-api-evidence.csv): **209** — структурный кандидат прокси с CFG-подтверждением границ, **3** — дополнительные совпадения регистрационного участка `GameScript.Game`, **1542** — только точная отдельная короткая строка, **2125** — без такой отдельной строки. Классы взаимоисключающие. Это число **путей в каталоге**, включая алиасы и редакторские API, не число реализаций или доказанных функций.
5. Из старых 179 кандидатов поиск расширен на другой вариант инструкций и сырые MSVC-ссылки на пространство имён вида `@2@`. Получено **209** кандидатов. Все 209 последовательностей достигнуты при статическом проходе по непосредственным переходам и fall-through из пяти предполагаемых начал функций после заполнения `int3`. Проверялись границы **всех инструкций последовательности**, а также шаблон конструктора, vptr, COL и RTTI. В пяти диапазонах получено 0 ошибок декодирования и 0 косвенных переходов, не прослеженных алгоритмом: [cfg-anchor-summary.csv](cfg-anchor-summary.csv). Начало после `int3` — обоснованная эвристика, а не метаданные границ функций. Граф не проверяет выполнимость условий и не доказывает, что игра достигает участка.
6. В функции с предполагаемым началом `0x127DD20` по **всем 161** коротким именам namespace `GameScript.Game` найдены достижимые в этом графе инструкции `push` и вызовы конструкторов прокси с RTTI-токеном `GameScriptGame`: [gamescript-game-all-methods.csv](gamescript-game-all-methods.csv). Для 158 имеются дополнительно автоматические кандидаты с непосредственно заданным адресом функции; у `Kill`, `DataMinerCheckpoint` и `AdjustPossessionVisionModeForCinema` аргумент в данном участке передаётся через регистр, поэтому автоматический отчёт не выдаёт его за немедленный адрес.

**Важно о границах поиска:** отсутствие точной строки — не доказательство отсутствия реализации. Для поиска целых ASCII-строк требуются NUL в конце и либо NUL в начале, либо начало секции; строки, начинающиеся после ненулевого байта, закодированные или генерируемые имена могут быть пропущены. Сравнение полного пути API с нативным namespace основано на согласовании имён; сам механизм связывания полного Lua-пути не восстановлен. MSVC-токен `@2@` сохранён как back-reference без утверждения о полном деманглинге. Имена `ClassMethodProxy…N` сравниваются с числом параметров заглушки как **два числовых наблюдения**, а не как доказательство совпадения ABI, типов, `this`, необязательных параметров или поведения.

## Ручная проверка после работы скриптов

Просмотрены результаты всех 161 строк таблицы и отдельно проверены ниже перечисленные шесть расхождений, как содержимое заглушек и справочника, так и декодированные инструкции, конструкторы, vtable → COL → RTTI. Пять начальных адресов CFG вручную осмотрены: перед ними стоят `ret` и `int3`, а сами адреса начинаются с типичных прологов. Это поддерживает выбор начальной границы, но не превращает CFG в трассировку реального исполнения. Дополнительная ручная проверка не проводилась для каждой из 3879 записей или для всех машинных инструкций; результаты строкового и структурного поиска не называются доказанными runtime-связями.

Адреса инструкций и шесть фрагментов конструкторов записаны в [manual-review-excerpts.txt](manual-review-excerpts.txt). Адреса ниже — preferred VA при image base `0x400000`.

| Запись `GameScript.Game` | Суффикс числа параметров в RTTI-прокси | Параметров в Lua-заглушке | `push` строки / конструктор прокси |
|---|---:|---:|---|
| `AdjustPossessionVisionModeForCinema` | 2 | 0 | `0x12800E3` / `0xC37430` |
| `DataMinerCheckpoint` | 1 | 0 | `0x12800B7` / `0x853D50` |
| `KillAllObjectsInWeaponInventory` | 1 | 0 | `0x127FB6F` / `0x8F4CB0` |
| `ShowLoadingScreenMovieStreamHint` | 4 | 0 | `0x127F575` / `0xA18740` |
| `ShowLoadingScreenMovieStreamHintWithMenu` | 5 | 0 | `0x127F5A8` / `0xC19A20` |
| `ShowMovie` | 2 | 3 | `0x127F4DC` / `0xE775C0` |

Документ `docs/reference/GameScript.Game.md` и `luasense_decompiled.lua` содержат именно показанные формы заглушек. Например, в заглушке `ShowMovie(arg1, arg2, arg3)` — три параметра, а RTTI выбранного прокси содержит `ClassMethodProxy_void_const2<…, GameScriptGame, …>`. На `0x127F4D6` для строки `ShowMovie` передаётся адрес `0x43E8A0`; проверенный конструктор записывает имя и адрес в поля `+0x10` и `+0x20`, затем устанавливает vptr `0x146B488`. Его COL/RTTI содержит указанный `void_const2`. Обёртка `0x43E8A0` читает два стековых аргумента, добавляет третий со значением 0 при вызове `0xAD8CD0` и возвращается через `ret 8`. Это конкретное наблюдение о машинном коде, но оно **не** устанавливает автоматически, как Lua-слой обрабатывает третий аргумент или существуют ли другие регистрации.

Для `DataMinerCheckpoint` ручной разбор показывает `push ebx` на `0x12800B6`; в начале функции на `0x127DD41` EBX получает `0xB7F4C0`, а в просмотренном декодированном теле нет других явных записей в EBX. По стандартному x86 calling convention EBX сохраняется вызываемыми функциями; при этом допущении передаваемый адрес — `0xB7F4C0`, где находится `ret 4` без другой инструкции. Это не равно доказательству, что любой Lua-вызов в работающей игре всегда пустой: ABI всех промежуточных вызовов, состояния и полного регистрационного пути отдельно не подтверждены.

Во внешнем API присутствует и `GameScript.FEAR.GameDebugDump`; регистронезависимый поиск по всем байтам EXE не нашёл `GameDebugDump` в ASCII, UTF-16LE или UTF-16BE. С этим именем остаётся отрицательный буквальный результат, а не доказательство невозможности аналогичной функции под другим именем.

## Что остаётся неподтверждённым

* 209/212 кандидатов не доказывают полный Lua binding и фактическое выполнение; `GameScript.Game` — одна группа из множества, и совпадение 161 имён не подтверждает семантику 161 методов.
* Сопоставление по коротким строкам не идентифицирует namespace. Редакторские API вроде `Despair.Forge.*` не следует считать игровыми функциями только из-за одинакового слова в PE.
* Для 6 различий нельзя без дополнительного исследования объявить ошибочной именно документацию или конкретную сборку EXE. Внешний snapshot и EXE могут происходить из разных сборок; заглушки не являются исходной реализацией.
* Нужны полный разбор механизма регистрации и преобразования типов, проверка всех прочих namespace/косвенных ссылок и при необходимости безопасная проверка на совместимой изолированной среде. Без этого «совпадают все» не обосновано.

## Скрипты, тесты и воспроизведение

```sh
python tooling/install.py                             # если локальных зависимостей нет
python tooling/fetch_lua_api.py                       # только если снимок отсутствует
python tooling/verify.py --exe 'evidence/source-exe/F.E.A.R. 3.exe'
python tooling/extract_script_classes.py
python tooling/audit_script_api.py
python tooling/test_script_api_audit.py
```

`audit_script_api.py` вызывает предыдущий сравнительный генератор и создаёт CSV отчёта. `test_script_api_audit.py` проверяет охват секций и документов, разбиение 3879 записей, 209 CFG-кандидатов, 161 запись и шесть расхождений, а также отказ при подменённом EXE или архиве API. Тесты не заменяют независимую проверку правильности всех предположений о PE, RTTI или Lua ABI. Исходный EXE исключён из Git и должен совпадать с SHA-256 `caa1f80d49da5dbadee3b1a44c470a87ffcb6afa8c0ed24af01741a155c326c2`; API закреплён на commit `4a7a7cf3d48f09dca446441d8af427f30556280d`.
