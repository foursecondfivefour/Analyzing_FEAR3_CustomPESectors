# C++: полный доступный статический инвентарь имён

## Охват и результат

Исследован **не запуская его** `F.E.A.R. 3.exe`, 22 411 776 байт, SHA-256 `caa1f80d49da5dbadee3b1a44c470a87ffcb6afa8c0ed24af01741a155c326c2`, PE32 x86, preferred image base `0x400000`. Побайтово просмотрены сырые диапазоны **всех 35 секций** (22 409 728 байт суммарно, включая raw padding): три стандартные начальные секции, 31 предоставленная пользовательская и `.rsrc`. Заголовки PE, данные вне секций/overlay и виртуальный zero-fill в этот проход не входят; чтение не переходит границы секций. Проверены SHA-256 EXE и метаданные/хеши 31 секции по исходному манифесту. Отдельный `verify.py` дополнительно сверяет извлечённые файлы с EXE. Это совпадение источников, **не доказательство подлинности EXE**.

Главная точка входа — [`names.csv`](names.csv): **14 961 различных точных написаний**, включая шаблонные типы, со счётчиками источников и указателями на RTTI. Это объединение имён и кандидатов/упоминаний, **не доказательство 14 961 различных реализованных классов**: разные написания могут относиться к одному типу, а импортируемые типы и аргументы шаблонов не обязательно реализованы или имеют RTTI в EXE. Исходные свидетельства, а не только сводные названия, сохранены в таблицах ниже.

| Наблюдение | Количество |
|---|---:|
| Сырые вхождения префикса `.?A` во всех секциях | 11 951, все в `.data` |
| Кандидаты MSVC TypeDescriptor | 11 951 уникальных декорированных имён: 11 832 `class` и 119 `struct` по маркеру |
| Раскодированы Wine demangler | 11 950; одно исходное имя сохранено как `unresolved` |
| Дескрипторы с кандидатами COL и виртуальной таблицы | 9 656 |
| Остальные дескрипторы без найденного COL | 2 295 |
| Кандидаты Complete Object Locator (COL) | 15 473, все в `.rdata` |
| Уникальные иерархии / строки дескрипторов баз | 9 656 / 38 310, включая self-элемент |
| Кандидаты виртуальных таблиц | 15 473; ещё 1 сырое совпадение отклонено |
| C++-имена символов в обычных экспортах / импортах | 199 / 258 |
| Строки упоминаний типов внутри RTTI-имён | 18 384; 2 949 различных точных написаний не совпали с именем собственного RTTI |
| Различные имена из символов без точного совпадения с RTTI | 63; из экспортов 27, из импортов 36 |

Последние два счётчика пересекаются друг с другом и не являются суммой новых классов. Импорты — свидетельство **ссылки на внешнюю DLL**, не доказательство реализации в EXE. При отсутствии точного совпадения с RTTI нельзя утверждать отсутствие RTTI из-за различий в написании, поддержке деманглера или эвристики.

## Файлы

- [`names.csv`](names.csv) — общий алфавитный указатель точных написаний. `rtti_descriptors` — адреса TypeDescriptor (через `;`), остальные числа — количество строк свидетельств из отдельных реестров. Нераскодированное имя помечено `decorated_unresolved`. Строки без RTTI являются только кандидатами/упоминаниями.
- [`classes.csv`](classes.csv) — по строке на найденный TypeDescriptor, включая полные `decorated_name`, вид `class`/`struct`, demangle-статус, raw-offset, адреса и числа ссылок. 2 295 строк без COL не отбрасываются.
- [`raw-name-candidates.csv`](raw-name-candidates.csv) — все вхождения `.?A`, включая потенциальные отклонения с причиной и полное корректное ASCII-имя. Для некорректных или не завершающихся NUL строк диагностический фрагмент ограничивается 512 байтами; raw-offset указывает на оригинал.
- [`complete-object-locators.csv`](complete-object-locators.csv) — сырые кандидаты COL, указатель на тип, смещения подобъекта, иерархия и число баз.
- [`base-descriptors.csv`](base-descriptors.csv) — элементы base-class array для каждой уникальной иерархии: порядок, имена, `contained_bases`, `mdisp`, `pdisp`, `vdisp`, атрибуты. Это перечисление иерархии MSVC, **не список только непосредственных родителей**. Первая запись — сам тип.
- [`vtable-candidates.csv`](vtable-candidates.csv) — расположение каждой проверенной ссылки на COL и первого слота; `candidate` либо причина отклонения. 5 292 кандидата в `.rdata`, 5 825 в `Game_dat`, остальные — в других данных, см. CSV.
- [`rtti-type-references.csv`](rtti-type-references.csv) — явно упомянутые `class`/`struct` в раскодированных аргументах типов; ссылки на дескриптор-владелец и точное совпадение с RTTI при наличии. Это эвристическое извлечение, не полный синтаксический разбор C++.
- [`cpp-symbols.csv`](cpp-symbols.csv) — все MSVC-декорированные имена из обычных export/import directories, декодированный прототип, адрес export или IAT import, DLL и offset строки; оригинал сохранён, включая нераскодированный символ.
- [`symbol-type-references.csv`](symbol-type-references.csv) — кандидаты владельца метода и явные `class`/`struct`-типы в прототипах; обратная связь через `symbol_id` и DLL. Импорты и экспорты разделены.
- [`section-coverage.csv`](section-coverage.csv) — raw-диапазоны, VA/RVA-метаданные, SHA-256 и количество сырых попаданий по каждой секции. [`summary.json`](summary.json) — машинные итоги.

`preferred VA = image_base + RVA`, без учёта ASLR/релокаций. `file_offset` — смещение именно в EXE. Имена секций в CSV отображаются без пробелов заполнения; для однозначности есть номер секции. В `cpp-symbols.csv` адрес импортируемого символа — слот IAT, а не адрес функции DLL.

## Методика и уровни доказательности

1. По каждому raw-байту секции ищется `.?A`; записываются даже непринятые совпадения. Принимаются NUL-завершённые printable ASCII имена длиной не менее 7 байт с `.?AV`/`.?AU` и предшествующим 8-байтным x86-заголовком: spare равен нулю, vftable указатель raw-backed, первый слот попадает в raw-backed исполняемую секцию. Это **кандидат**, не полная проверка синтаксиса MSVC. Скрипт не использует жёстко заданный адрес type_info vftable: в данном EXE у всех кандидатов он оказался `0x14AA224`.
2. По всем секциям, включая невыровненные позиции, ищутся 32-битные little-endian абсолютные ссылки на кандидатов TypeDescriptor. Из них отбираются x86 COL: signature 0, `offset`/`cdOffset` не более `0x10000`, raw-backed CHD signature 0, количество баз 1–1024, доступные массив и все 24-байтные дескрипторы; первый базовый тип совпадает с типом COL. Поля баз и флаги не доказывают корректность всех отношений. В этом EXE все найденные COL выровнены. Не прошедшие ограничения конструкции не включены в COL CSV; raw-ссылки без структурной проверки не являются COL.
3. Во всех секциях ищутся ссылки на COL, за которыми следует указатель в raw-backed исполняемый диапазон. Таблица начинается **после** ссылки на COL. Выровненная позиция в неисполняемой секции считается кандидатом, но может оказаться данными, а первый слот — thunk или ложное совпадение. В `.text` есть отклонённое невыровненное совпадение `0x7C8D99`, COL `0x158247C`: оно сохранено с причиной. Это не установленная таблица.
4. Имена `.?AV`/`.?AU` декодируются через Wine-derived `undname` 0.2: формируется **искусственное** `??_7…6B@` и убирается суффикс результата vftable. Искусственная строка нужна только для разбора имени и сама по себе не подтверждает существование таблицы. Версия, хеш архива и LGPL-2.1-or-later указаны в установщике; лицензия и исходники сохраняются рядом с собранной библиотекой локально. Возможны ошибки декодирования и нестандартные имена. Для одного длинного имени `0x17528B8` результат не получен; похоже на сокращённое/хешированное имя, но мы не восстанавливаем недостающие символы и сохраняем точные исходные байты.
5. Отдельно читаются обычные импорты и экспорты PE. Из декодированных прототипов эвристически выделяются `class`/`struct` и владельцы методов с access qualifier и calling convention; вложенные шаблоны поддерживаются ограниченным разбором скобок. Не все символы и типы охватываются; декодер не гарантирует идеальную семантику. Статические данные, нетипичные операторы, другие ABI, имена только в коде/ресурсах и сложные конструкции могут быть пропущены.

Бинарник содержит ссылку на PDB `Game_wf.pdb`, но сам PDB здесь не анализировался; COFF symbol table отсутствует. Классы без сохранившихся имён и RTTI, локальные или оптимизированные типы, классы внешних DLL, закодированные/сжатые данные, delay imports, данные заголовков/overlay и runtime-генерируемые типы не покрываются полностью. Никакой статический поиск этих сигнатур не доказывает, что найден **каждый** исходный класс или что тип используется во время выполнения.

## Ручные опорные примеры

- `Despair::GameScriptPlayer`: TypeDescriptor `0x169B418`, имя по file offset `0x1299C20`; COL `0x153B0D0` и `0x153B128`, иерархия `0x153B0E4`; два кандидата таблиц `0x1870E7C` и `0x1870E74` находятся в `Game_dat`, а не в `.rdata`. Иерархия включает `IAutomationElement`, `Reflection::QueryObject`, `Reflection::Object`, `Reflection::IQueryObject`; не все они обязательно непосредственные родители.
- `Despair::PlayerProfile`: TypeDescriptor `0x1623040`, COL `0x15F2818`/`0x15F282C`, кандидаты таблиц `0x14F012C`/`0x1452078`; смещения подобъекта COL `0` и `4` соответственно. Указатель на type_info vftable — не таблица самого PlayerProfile.
- `Despair::Vector3d` встречается как явный аргумент RTTI-имени, но не имеет точного совпадения в `classes.csv`; это упоминание типа, не доказательство отдельного найденного TypeDescriptor. Символы экспорта дают, например, `GThread`; импорт FMOD даёт `FMOD::System`, отдельно маркированный как внешний.

## Воспроизведение и проверки

Нужны соответствующий локальный EXE по пути `evidence/source-exe/F.E.A.R. 3.exe`, Python 3, `pefile==2024.8.26`, для полного деманглинга — Linux, `gcc` и интернет для однократной установки. Файлы EXE и локальные инструменты в Git не включаются. Загрузки делаются Python/pip; деманглер загружается с PyPI через Python, архив проверяется закреплённым SHA-256 и извлекаются только фиксированные файлы.

```sh
python -m pip install --target tooling/python pefile==2024.8.26
python tooling/install_undname.py
python tooling/verify.py --exe 'evidence/source-exe/F.E.A.R. 3.exe'
python tooling/inventory_cpp_classes.py
python tooling/verify_cpp_classes.py
python -m unittest discover -s tooling -p 'test_inventory_cpp_classes.py' -v
```

Без gcc/деманглера можно использовать `python tooling/inventory_cpp_classes.py --no-demangler --out /path/to/output`: останутся все 11 951 исходных RTTI-имён, но только 5 030 простых имён будут раскодированы; ссылки внутри сложных имён и символов не извлекутся. Используйте **другой** `--out`, чтобы не перезаписать полный опубликованный реестр. Другой PE32 x86 можно явно указать через `--exe`, `--sha256` и при необходимости `--manifest`; алгоритм не является универсальным сканером всех ABI/упаковок. Для другой сборки нет независимой проверки опубликованных здесь результатов.

Независимый `verify_cpp_classes.py` заново проходит каждый байт каждой секции на `.?A`, сверяет все позиции и хеши секций, читает с диска имена, заголовки RTTI, COL, иерархии, базовые дескрипторы, слоты vtable и строки символов, сравнивает все 11 951 RTTI с прежним инвентарём. Сопоставлены и все 5 030 простых имён прежнего скрипта: расхождений нет. Шесть новых unit-тестов покрывают некорректный COL, проверку манифеста, невыровненные указатели, ложный кандидат в коде, синтаксис имён и fallback. Повторная генерация всех CSV и JSON побайтово совпала; неверный SHA-256 отклонён. Проверки подтверждают согласованность с данными и заданными правилами, а не полноту или правильность интерпретации всех C++ типов.
