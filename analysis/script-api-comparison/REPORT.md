# Сравнение PE-классов со справочником Lua API

## Вывод

Сопоставлены ранее извлечённые 149 простых RTTI-типов и [указанный справочник API](https://github.com/foursecondfivefour/FEAR3-DespairEngineLuaAPI/blob/4a7a7cf3d48f09dca446441d8af427f30556280d/docs/API.md), а также связанные с индексом записи `api/despair-api.json`. Главный результат: **это разные уровни описания**. В EXE видны C++-типы и reflection-прокси; в справочнике — пути функций и пространства имён Lua, в том числе инструменты и алиасы. Прямое равенство названий классов и путей ожидать нельзя.

* В индексе API — **330 пространств имён и 3879 записей**, включая алиасы; индекс и JSON совпадают по количеству записей в каждом пространстве имён. Это не 3879 независимых реализаций. В `GameScript` и `GameScript.*` находятся **626 записей**.
* Ни один из **149** коротких имён нативных RTTI-классов не совпал целиком с отдельным компонентом пути в 3879 записях API. Для **21** класса `GameScript…` обнаружены кандидаты по строгому совпадению суффикса с последним компонентом игрового пространства имён: например, `GameScriptPlayer` → `GameScript.Game.Player`. Это сопоставление имён, **не доказательство регистрации**.
* Во всех 35 PE-секциях для **625 из 626 путей `GameScript`** найдено точное совпадение их последнего компонента с отдельной NUL-терминированной ASCII-строкой. Это 625 путей документации с совпавшей строкой, а не 625 доказанных функций: одинаковые короткие имена могут использоваться в разных пространствах, а функция может не регистрироваться или не вызываться.
* Дополнительный структурный поиск нашёл **179 кандидатов** связей `имя метода → адрес функции → reflection-прокси с конкретным классом GameScript` с совпадением пути в API. Четыре примера дополнительно проверены дизассемблированием. Для остальных 175 границы машинных инструкций и вся цепочка регистрации по отдельности не проверялись; сам алгоритм не охватывает все формы регистрации.

Аналогично, `LuaScriptHost`, `LuaScriptThread`, `IScriptHost`, `ScriptComponent` и другие классы инфраструктуры не становятся пространствами `GameScript.*` автоматически. Некоторые имена классов при этом упоминаются внутри текста call-tip — это отличается от совпадения пути API. Отрицательный результат **не** означает, что эти типы не используются движком или не доступны косвенно.

## 2. Примеры с проверенными инструкциями и RTTI прокси

Здесь доказана локальная нативная связь имени, функции и типа reflection-прокси. Полный путь Lua из документации сопоставлен по имени и структуре API; сам механизм runtime-поиска именно этого пути целиком не прослежен. Исходные байты и дизассемблирование: [reviewed-bridges-asm.txt](reviewed-bridges-asm.txt), полные декорированные имена: [typed-proxy-pattern-candidates.csv](typed-proxy-pattern-candidates.csv).

| Путь API (сопоставление по имени) | Тип внутри RTTI прокси | Участок передачи имени | Нативный адрес | Конструктор прокси | Vtable / COL |
|---|---|---:|---:|---:|---|
| `GameScript.Game.StreamWorlds` | `GameScriptGame` | `0x127F9CE` | `0xC316A0` | `0x82C4A0` | `0x146B6C8` / `0x1542E28` |
| `GameScript.Game.SetAnimationGraphResource` | `GameScriptGame` | `0x127F197` | `0x93CC90` | `0x67B820` | `0x146B3A8` / `0x154252C` |
| `GameScript.Game.Player.RevivePlayerInstant` | `GameScriptPlayer` | `0x1272F2D` | `0x97B080` | `0xA82000` | `0x1469760` / `0x153A3AC` |
| `GameScript.Support.RegisterAnimationGraphResourceVariable` | `GameScriptSupport` | `0x1275094` | `0xD27790` | `0x981300` | `0x1469CA0` / `0x153BE3C` |

Например, на `0x127F9D1–0x127F9DC` код передаёт `0xC316A0` и указатель на строку `StreamWorlds` (`0x18788A8`) в `0x82C4A0`. Конструктор записывает первый аргумент в поле объекта `+0x10`, адрес функции — в `+0x20`, а на `0x82C4D4` устанавливает vptr `0x146B6C8`. COL этой таблицы ведёт к декорированному типу `ClassMethodProxy_void_const2<…, GameScriptGame, …>`. Созданный объект передаётся функции `0x77AC20` на `0x127F9EA`. Это сильнее простого текстового совпадения: показана последовательность машинных инструкций и RTTI типа прокси. Но ни тип прокси, ни похожее имя документации сами по себе не подтверждают, что именно этот вызов был выполнен в игре.

Для `StreamWorldsWithSaveOverride` ранее отдельно прослежены аналогичная передача имени и обёртка: см. [предыдущее сопоставление Resource](../resource/lua-correlation/REPORT.md). Адрес целевой функции `0x9DA070`; её прокси-RTTI также содержит `GameScriptGame`. В документации `StreamWorlds` имеет два placeholder-аргумента, а `StreamWorldsWithSaveOverride` — три; placeholder-имена не являются восстановленными именами параметров C++.

## 3. Массовые кандидаты связей

Алгоритм ищет в `.text` фиксированный байтовый шаблон передачи адреса функции и строки в конструктор, с последующей передачей результата вызову; затем проверяет фиксированный шаблон конструктора, его vptr, COL и RTTI `ClassMethodProxy` с вложенным `GameScript…`. Наконец сравнивает короткое имя метода с записями API в namespace, полученном правилом из раздела 1. Все адреса и полные RTTI сохранены в CSV.

| Класс в RTTI прокси | Количество кандидатов |
|---|---:|
| `GameScriptGame` | 128 |
| `GameScriptPlayer` | 23 |
| `GameScriptSupport` | 11 |
| `GameScriptFEAR` | 10 |
| `GameScriptPhysics` | 7 |
| **Всего** | **179** |

Четыре примера из раздела 2 проверены вручную по дизассемблированию с конкретных границ инструкций. Для прочих это **структурные кандидаты**, а не по отдельности подтверждённые runtime-маршруты: байтовый шаблон может начинаться внутри иной инструкции, общий конструктор может вызываться в других контекстах, а API-путь получен сопоставлением имён. Другие шаблоны инструкций, косвенные переходы, способы регистрации и имена вне `GameScript.*` анализом не охвачены. Поэтому отсутствие записи в 179 кандидатах не означает отсутствия нативной реализации. Также количество кандидатов не равно числу методов, работающих в игре.

## 4. Отличие, найденное в именах

Из 626 путей `GameScript` единственный без совпадения короткого имени в указанном ограниченном поиске строк — **`GameScript.FEAR.GameDebugDump`**. Дополнительно выполнен регистронезависимый поиск `GameDebugDump` по **всему EXE**: 0 сырых совпадений в ASCII, UTF-16LE и UTF-16BE. Каталог API содержит такую запись и заглушку; в данном EXE её буквального имени не обнаружено. Это не доказывает отсутствие эквивалентной функции под другим именем, в сжатом/динамическом виде либо во внешней библиотеке.

Все результаты для API: [api-entry-exact-leaf-strings.csv](api-entry-exact-leaf-strings.csv). Полные NUL-строки искались только внутри файловых байтов PE-секций; для снижения ложных совпадений требуется начало секции либо предыдущий нулевой байт. Такой критерий может пропустить настоящую строку, расположенную после ненулевого байта. Совпадение короткой строки в PE не подтверждает сам Lua-путь и может относиться к другой подсистеме. Например, 1754 из 3879 **путей каталога** имеют такое совпадение — не следует интерпретировать это как количество реализованных функций, особенно для `Despair.Forge.*` и других редакторских API.

## 5. Воспроизведение и файлы

```sh
python tooling/install.py                         # если отсутствуют Python-зависимости
python tooling/fetch_lua_api.py                   # только при отсутствии external/lua-api
python tooling/verify.py --exe 'evidence/source-exe/F.E.A.R. 3.exe'
python tooling/extract_script_classes.py
python tooling/compare_script_api.py
```

Требуется EXE с указанным хешем, исключённый из Git. Сравнение проверяет хеш EXE и исходного снимка, содержание 622 файлов, хеш `API.md`, соответствие 330 строк индекса JSON и все 149 сохранённых RTTI-имён; затем генерирует CSV и проверенные выдержки. Текущий `main` меняется независимо; воспроизводится именно закреплённая ревизия.

Файлы: [сопоставление классов](class-namespace-comparison.csv), [совпадения коротких имён API](api-entry-exact-leaf-strings.csv), [179 кандидатов proxy-цепочек](typed-proxy-pattern-candidates.csv), [проверенные фрагменты кода](reviewed-bridges-asm.txt), [статистика и хеши](stats.json).
