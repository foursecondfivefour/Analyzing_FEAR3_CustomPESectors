# Статический каталог кандидатов функций PE F.E.A.R. 3

## Что именно собрано

Скомбинированы результаты нескольких Python-скриптов: PE exports/imports (`pefile`), RTTI и кандидаты vtable из `analysis/cpp-classes`, регистрационные кандидаты из `analysis/script-api-audit`, декодирование x86 через Capstone, прямое побайтовое сканирование и классификация по сохранившимся именам. EXE не запускался. Все 35 raw-секций идентифицированы и захешированы; кодовые эвристики применены ко всем секциям с флагом executable — в этой сборке это одна `.text`, 16 707 072 raw-байта.

**Главное ограничение:** это не «абсолютно все функции C++». Без исходников, совпадающих PDB/символов или надёжного восстановления всех границ и динамических целей доказать такую полноту нельзя. Каталог объединяет и данные компилятора, runtime, thunk и обычный C/библиотечный код; часть адресов может вообще не быть началом функции. Отдельные функции могли быть встроены, удалены, слиты или содержать непрямые переходы. Поэтому единица учёта — **уникальный адрес-кандидат**, а не исходная функция или класс. Мы не назначаем вымышленные имена, сигнатуры и семантику без свидетельств.

Объект анализа: локальный PE32 x86, 22 411 776 байт, SHA-256 `caa1f80d49da5dbadee3b1a44c470a87ffcb6afa8c0ed24af01741a155c326c2`; image base `0x400000`. Все адреса — preferred VA, не runtime VA при ASLR. Совпадение хеша фиксирует конкретный экземпляр, но не устанавливает его подлинность.

## Категории

[category-summary.csv](category-summary.csv) и `category_tags` в основном CSV содержат категории: `script_api`, `graphics_rendering`, `audio_video`, `physics_animation`, `network_multiplayer`, `gameplay_ai`, `ui_menu`, `resource_io`, `math_geometry`, `memory_containers`, `threading_sync`, `platform_system`, `reflection_rtti`, `unknown`. Это многозначные **эвристические** теги по регулярным выражениям из `RULES` в генераторе: используются сохранённые экспортные имена, имена импортов для соответствующих jump и имя типа, связанного с vtable, а также факт связи с script API. Они могут ошибаться, особенно на вложенных шаблонах: класс, переданный параметром шаблона, не обязан быть владельцем реализации. Отнесение по vtable — ассоциация с типом, а не доказательство, что функция определена именно этим типом.

**84 912** адресов имеют `unknown`: им не найдено достаточного текстового основания для тега. Категории пересекаются, их количества складывать нельзя. `script_api_names` обозначает соответствие имени записи/прокси, а не доказанную совместимость ABI или binding во время выполнения; builder и цель могут иметь одну и ту же метку API, но различаются в `evidence_sources` и `named-evidence.csv`. Экспортное имя в `export_names` может содержать несколько алиасов и не устанавливает границы функции.

## Файлы

* [function-candidates.csv](function-candidates.csv) — все адреса, смещение, приоритетная метка, все источники, сохранившиеся имена, категории и счётчики. Сортировка по категориям, затем по уровню и адресу. CSV хранит текст; числовые адреса имеют формат `0x...`.
* [named-evidence.csv](named-evidence.csv) — сохранённые экспортные прототипы и соответствия путям API, включая различие target/builder; не считать API-имя доказанным C++ символом.
* [vtable-word-evidence.csv](vtable-word-evidence.csv) — привязка адресов к TD, потенциальному типу, таблице и индексу слова. `later_word_not_proven_slot` — особенно слабая связь.
* [cfg-call-edges.csv](cfg-call-edges.csv) — инструкции прямых вызовов и разрешённых IAT-вызовов/переходов с адресами цели/IAT. Это ребра, не список границ функций; вызывающая функция намеренно не приписывается.
* [raw-e8-calls.csv](raw-e8-calls.csv) — все сырые совпадения, включая неинструкции; [padding-entry-candidates.csv](padding-entry-candidates.csv) — кандидатные начала после `CC`; [iat-jump-patterns.csv](iat-jump-patterns.csv) — сырые импортные jump-шаблоны и отметка CFG.
* [imports.csv](imports.csv) — обычные PE-импорты и адреса IAT; не копии внешнего машинного кода.
* [summary.json](summary.json) — объёмы, теги, hashes и ограничения; [verification.json](verification.json) — результаты независимой перепроверки.

## Метод и границы

1. Для каждого сохранённого кандидата vtable читается не более 256 слов, пока значения указывают в raw-backed executable-секцию; чтение останавливается перед предыдущим COL следующей известной таблицы, при первом неисполняемом значении или границе секции. Соседние таблицы, литералы или указатели могут дать ложные последующие слоты. Ограничение может также пропустить настоящие слоты.
2. Глобальный ограниченный CFG запускается из PE entry, исполняемых экспортов, регистрационных target/builder и этих vtable-слов. Декодируются fallthrough, непосредственные условные/безусловные переходы и непосредственные вызовы, а вызовы получают обе ветви: цель и продолжение. Непрямые переходы не обходятся; IAT вызовы/переходы фиксируются отдельно. Это не выделяет отдельные функции и включает слабые начальные точки из последующих слов vtable.
3. Если два возможных декодирования пересекаются, принимается первое посещённое; 47 альтернативных стартов отброшено, ещё 3 декодирования не удались. Порядок стартов определён генератором. Глобально разобрано 3 481 839 инструкций и 10 235 905 уникальных байт `.text`; это не runtime coverage и не доказанная кодовая разметка. Сильные и слабые начальные точки в графе не разделены по происхождению, поэтому флаг CFG остаётся эвристическим.
4. Дополнительно найдены каждый E8 на любом смещении с исполняемой целью, максимальные серии `CC` и все сырые шаблоны `FF25` с адресом существующего IAT. Эти три эвристики сами по себе не являются семенами CFG и не доказывают границ инструкций.
5. `verify_cpp_functions.py` отдельно перепроверяет хеши секций, каждый адрес, все 380 192 E8-совпадения с полнотой сканирования, 237 775 сохранённых декодированных рёбер и operands, все 92 024 слова таблиц, первые слоты, все соответствующие padding/FF25-позиции, а также экспорты и импорты. Он проверяет **байтовую корректность и локальное декодирование рёбер**, но не воспроизводит глобальную достижимость CFG, не доказывает категорию, дальнейшие границы таблиц или полноту функций. Script API и RTTI имеют отдельные предыдущие отчёты и валидаторы.

## Ручные примеры

* `0x6C2D50` — первый слот кандидатной таблицы `0x1870E7C`, связанной с TD `0x169B418` (`Despair::GameScriptPlayer`). Это проверенная ассоциация первого слота, но не подтверждённое имя метода; `--owners` показывает связь.
* `0x43E8A0` — кандидат target регистрации `GameScript.Game.ShowMovie`; локальная x86-последовательность передаёт аргументы и вызывает `0xAD8CD0`, затем `ret 8`. Это не доказывает runtime binding или соответствия всей внешней сигнатуре Lua API.
* `0xF3B346`: байты `FF 25 88 06 3F 01`, локальное декодирование `jmp dword ptr [0x13F0688]`; IAT относится к `MSVCR90.dll!_CxxThrowException`. Сохранены 254 декодированных прямых вызова на этот адрес и 687 сырых E8-совпадений; второе число включает возможные неинструкции и не следует прибавлять к первому.

## Использование и воспроизведение

Поиск работает на уже сохранённых CSV и требует только стандартную библиотеку Python:

```sh
python tooling/query_cpp_functions.py --category script_api --source vtable_first_slot --limit 20
python tooling/query_cpp_functions.py --owner Despair::GameScriptPlayer --owners --limit 20
python tooling/query_cpp_functions.py --query ShowMovie
python tooling/query_cpp_functions.py --va 0x6C2D50 --owners
python tooling/query_cpp_functions.py --category unknown --tier raw_e8_target_only --format csv --limit 100
```

Фильтр `--query` ищет по экспортному имени, пути API и адресу; `--owner` отдельно просматривает все ассоциации типов. `--owners` выводит полные строки ассоциаций для найденных адресов; `--offset` и `--limit` позволяют постраничный просмотр. `--limit` ограничен 10 000; для полной выборки можно работать с CSV напрямую.

Для генерации и проверки нужны локальный проверенный EXE, CSV предыдущих RTTI/API-аудитов, `pefile` и `capstone`:

```sh
python -m pip install --target tooling/python pefile==2024.8.26 capstone==5.0.9
python tooling/inventory_cpp_functions.py
python tooling/verify_cpp_functions.py
python -m unittest discover -s tooling -p 'test_cpp_functions.py' -v
```

Генератор проверяет SHA-256 EXE до записи; поддерживает `--exe` и `--out`. Проверяющий скрипт по умолчанию читает местные результаты и исходный EXE. Для более точной и полной атрибуции необходимы соответствующие PDB/карта линкера, другой надёжный разбор кода или проверяемые динамические трассы; ни одного из этих источников здесь нет.
